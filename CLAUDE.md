# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Local development

The canonical way to run the site is via Docker (the `Dockerfile` pins Ruby 4.0 to match the GitHub Actions build):

```bash
./run-jekyll.sh         # macOS/Linux — wraps docker build + run, serves on :4000, livereload on :35729
./run-jekyll.bat        # Windows equivalent
```

Without Docker: `bundle install` once, then `bundle exec jekyll serve`. The repo currently lives in a tree where the host Ruby may not match the pinned 4.0; prefer Docker unless there's a reason not to.

Production builds run in GitHub Actions (`.github/workflows/github-pages.yml`) on every push to `master` with `JEKYLL_ENV=production`. There is no test suite — local rendering at `http://localhost:4000` is the only verification step.

## Architecture

This is a Jekyll site that consumes the `plainwhite` theme **as a gem** (see `Gemfile` and `theme: plainwhite` in `_config.yml`). The repo also contains `plainwhite.gemspec` because it was forked from the upstream theme — most of the heavy lifting (layouts, sass partials, assets) is provided by the installed gem, while files under `_layouts/`, `_includes/`, and `_sass/` in this repo **override** the gem's versions of the same filename. When investigating rendering, check the local override first; if absent, look in the installed `plainwhite` gem.

Theme behavior (sidebar name, social links, search, dark mode, analytics, etc.) is configured under the `plainwhite:` key in `_config.yml`, not via separate files.

### Bibliography pipeline

The site uses `jekyll-scholar` for academic-style citations:

- Source: `_bibliography/references.bib` (BibTeX), styled by `_bibliography/my.cls` (CSL).
- `_plugins/sanitize_links_in_bib.rb` monkey-patches `CiteProc::Ruby::Formats::Html` to `CGI.unescape_html` the `prefix`/`suffix` of citations. This exists because the CSL emits raw HTML (anchor tags) inside prefix/suffix, and CiteProc otherwise double-escapes it. Don't remove this plugin without auditing rendered bibliography output.

### Posts

- Files in `_posts/` follow `YYYY-MM-DD-slug.md`. Permalinks are `/:year/:month/:day/:title:output_ext` per `_config.yml`.
- Cross-link other posts with `{% post_url YYYY-MM-DD-slug %}` rather than hard-coded URLs.
- Frontmatter typically includes `layout: post`, `date`, `title`, `categories` (a list), `published`, and `hero_image` (path under `/assets/`). Hero images are rendered by `_layouts/post.html` above the title.
- Assets (hero images, diagrams) live in `assets/`. Drawio sources live in `assets/drawio/` and are exported to SVG/PNG checked into `assets/` directly.

## Conventions worth knowing

- Don't edit `Gemfile.lock` — it's in `.gitignore` and regenerated by `bundler-cache: true` in CI.
- `_site/` is the build output (gitignored). Don't commit it.
- The Ruby version in the Dockerfile (`ruby:4.0-slim`) must stay in sync with `ruby-version` in `.github/workflows/github-pages.yml`.
